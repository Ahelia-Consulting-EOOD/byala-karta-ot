## 3. Алгоритъм за съчетаване на населени места и спирки

### 3.1 Стратегия

Двустепенен подход: (1) административно текстово съчетаване, (2) пространствена близост като резерва.

### 3.2 Стъпка 1: Административно текстово съчетаване

Всяка БДП спирка има полета `oblast`, `municipal`, `city`. Алгоритъмът нормализира стойността на `city`:

1. **Премахване на районни квалификатори:** "София-град - район Витоша" -> "София-град"
2. **Премахване на кварални квалификатори:** "Бургас, кв. Сарафово" -> "Бургас"
3. **Премахване на префикси:** "с. Самораново" -> "Самораново", "гр. Разлог" -> "Разлог"
4. **Премахване на кодове:** "[6280] гр. ГЪЛЪБОВО" -> "ГЪЛЪБОВО"
5. **Специални съпоставки:** "София-град" -> "София", "Велико Търнов" -> "Велико Търново"

Приоритет на съчетаване:
1. **Име + Община** (name_muni): точно съвпадение на нормализираното име + общината
2. **Име + Област** (name_oblast): при множество ЕКАТТЕ кандидати, филтър по област
3. **Само по име** (name_only): ако има единствен кандидат

**Резултат от текстовото съчетаване:**

| Метод | Спирки | % |
|-------|--------|---|
| name_muni | 9,528 | 92.7% |
| name_only | 48 | 0.5% |
| name_oblast | 46 | 0.4% |
| Без съвпадение | 276 | 2.7% |
| Без стойност за city | 382 | 3.7% |
| **Общо съчетани** | **9,622** | **93.6%** |

### 3.3 Стъпка 2: Пространствена близост (Spatial Fallback)

За останалите 658 несъчетани спирки - намиране на най-близкото населено място в радиус от 5 km чрез формулата на Haversine.

**Резултат:** 633 от 658 допълнително съчетани.

### 3.4 Крайни резултати от съчетаването

| Метрика | Стойност |
|---------|----------|
| Общо БДП спирки | 10,280 |
| Съчетани с ЕКАТТЕ | 10,255 (99.8%) |
| Несъчетани | 25 (0.2%) |
| Уникални ЕКАТТЕ с >= 1 спирка | **1,939** |

### 3.5 Гранични случаи и ограничения

1. **Районни квалификатори в София:** 2,480 спирки с "София-град - район X" - всички коректно се маппват към ЕКАТТЕ 68134 (София)
2. **Правописни разлики:** "Велико Търнов" (БДП) vs "Велико Търново" (ЕКАТТЕ) - ръчно съпоставяне
3. **Множествена неяснота:** "Бяла" съществува в области Варна и Русе - разрешава се чрез общината
4. **Междуселищни пътища:** 24 спирки с "междуселищен път" - без административно съчетаване, покрити чрез пространствена близост
5. **Обезлюдени села:** 194 населени места без население - включени в анализа, но без практическо значение за покритието

## 5. Модел на данните

### 5.1 Основни същности

```
Settlement (EKATTE)
  PK: ekatte (string, 5 digits)
  name: string
  name_en: string
  type: enum("с.", "гр.", "ман.")
  oblast_code: string(3) -> FK Oblast
  obshtina_code: string -> FK Municipality  
  nuts1: string -> NUTS1
  nuts2: string -> NUTS2
  nuts3: string -> NUTS3
  lon: float (WGS84)
  lat: float (WGS84)
  population_permanent: integer
  population_current: integer
  population_date: date
  altitude_category: integer
  -- Computed --
  has_pt_access: boolean
  stop_count: integer
  -- Phase 2+ extension points --
  route_count: integer (nullable)
  service_frequency_daily: float (nullable)
  connectivity_score: float (nullable)
  transport_poverty_index: float (nullable)

BusStop (BDP)
  PK: id (integer)
  lon: float (WGS84)
  lat: float (WGS84)
  oblast: string
  municipal: string
  city: string
  road: string
  road_type: enum("улица", "път")
  settlement_ekatte: string -> FK Settlement (computed via matching)
  -- Inspection data (from BDP) --
  has_bus_bay: boolean
  has_fencing: boolean
  has_barriers: boolean
  has_lighting: boolean
  has_signs: boolean
  inspection_date: date
  inspector: string

Oblast
  PK: code (string, 3 letters)
  name: string
  name_en: string
  nuts3: string

Municipality  
  PK: code (string)
  name: string
  name_en: string
  oblast_code: string -> FK Oblast
  nuts3: string
```

### 5.2 Агрегирани изгледи (Views)

```sql
-- Покритие по области
CREATE VIEW v_coverage_by_oblast AS
SELECT 
  oblast,
  COUNT(*) as total_settlements,
  SUM(CASE WHEN has_pt_access THEN 1 ELSE 0 END) as settlements_with_pt,
  SUM(population_permanent) as total_population,
  SUM(CASE WHEN has_pt_access THEN population_permanent ELSE 0 END) as population_with_pt
FROM settlement
GROUP BY oblast;

-- Покритие по NUTS2
CREATE VIEW v_coverage_by_nuts2 AS
SELECT 
  nuts2,
  COUNT(*) as total_settlements,
  SUM(CASE WHEN has_pt_access THEN 1 ELSE 0 END) as settlements_with_pt,
  SUM(population_permanent) as total_population,
  SUM(CASE WHEN has_pt_access THEN population_permanent ELSE 0 END) as population_with_pt
FROM settlement
GROUP BY nuts2;
```

### 5.3 Разширяемост

Моделът е проектиран така, че добавянето на Фаза 2+ данни не изисква промени в схемата на Фаза 1:

- **Фаза 2 (Маршрутни данни):** Добавяне на таблица `Route` и `RouteStop` (M:N). Полето `route_count` в Settlement се изчислява от JOIN.
- **Фаза 3 (Индекс за транспортна бедност):** Полето `transport_poverty_index` в Settlement се изчислява от композитна формула. Добавяне на таблица `PovertyIndicator` за съхранение на компонентите.

## 8. Поетапен план за имплементация

### Фаза 1: Бинарно табло за наличие на ОТ (ТЕКУЩА)

**Входни данни:**
- ЕКАТТЕ: 5,256 населени места (NSI, актуални към 01.2026)
- Население: ГРАО, актуално към 03.2026
- Координати: yurukov/Bulgaria-geocoding (OSM-базирани)
- БДП спирки: 10,280 (GIS Cloud, актуални към 02.2026)

**Резултат:**
- Обединен JSON: `bg_settlements_with_pt.json`
- Всяко населено място: има/няма достъп до ОТ, брой спирки
- Агрегации по NUTS2, област, община

**Ключови показатели:**
- 36.9% от населените места имат поне 1 спирка
- 80.7% от населението живее в населено място с поне 1 спирка
- 19.3% от населението (~1.53 млн. души) е без достъп до ОТ спирка

### Фаза 2: Интеграция на маршрутни данни

**Цел:** Преминаване от бинарно "има/няма спирка" към "има/няма реално обслужване"

**Източници:**
- Маршрутни разписания от транспортни оператори
- GTFS данни (ако са налични от градски транспорт)
- Автогари от БДП (453 записа, layer 6542289)

**Нови метрики:**
- Брой маршрути, обслужващи населеното място
- Дневна честота на обслужване
- Destinations (до кои градове има директна връзка)

### Фаза 3: Индекс за транспортна бедност

**Цел:** Композитен индикатор по рамката на ЕС

**Компоненти (от EU policy research):**
- Пространствен достъп (Фаза 1 - наличие на спирка)
- Времеви достъп (Фаза 2 - честота на обслужване)
- Социално-икономически фактори (доход, автомобилизация, възраст)
- Финансов достъп (цена на билет / доход)

**Формула:** `TPI = w1*spatial + w2*temporal + w3*socioeconomic + w4*financial`
